01

Distributed Systems

Most online services run on many machines that fail, slow down, and disagree. We design protocols and runtimes that keep these services correct and responsive anyway.

Questions we ask

  • How can replicas stay consistent without paying for it on every request?
  • How should a system detect and recover from partial failures?
  • How should work be scheduled when machines differ in speed?

02

Systems for AI

Training and serving large models is expensive. We study the software stack underneath them to get more useful work from the same hardware.

Questions we ask

  • How can GPU clusters be shared fairly and kept busy?
  • How can model serving meet latency targets at lower cost?
  • Where do memory and network bottlenecks limit training?

03

AI for Systems

Computer systems have more settings and failure modes than people can track by hand. We explore where learned models can help operators, and where they cannot be trusted.

Questions we ask

  • Can models tune system settings safely while the system is running?
  • Can they find the root cause of an outage from logs and metrics?
  • What guarantees are needed before automating a decision?

04

Cloud and Edge

Not every request should travel to a distant data center. We look at how to split computation between the cloud and devices closer to users.

Questions we ask

  • Which parts of an application belong at the edge?
  • How can models run well on devices with limited power and memory?
  • How should a system behave when the network is slow or unavailable?
